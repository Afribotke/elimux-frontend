NEW BLOCKING BUG — award_points() has no EXECUTE grant for the authenticated role
The same authenticated-test-user round trip above then called award_points and got a real, reproducible error:
  {"code":"42501","message":"permission denied for function award_points"}
Checked directly: has_function_privilege() confirms `authenticated` and `anon` both get `false` for EXECUTE on both award_points overloads; only `service_role`/`postgres` can call it. The function is SECURITY DEFINER, but that doesn't matter if the calling role was never granted EXECUTE in the first place. Since the app calls this through the normal user-session client (PostgREST as `authenticated`, not the service role), every award_points call from real app code fails with this error — silently, since my share-events route wraps it in after() with no error surfaced to the client or user.
Fix written to elimux-sql/54_grant_award_points_execute_to_authenticated.sql (two GRANT EXECUTE statements, one per overload) — not run yet, needs the same manual paste as the last two.
